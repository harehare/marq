Agent IDE

Everything you need to run agents side by side

Each task gets its own git worktree and branch, so several agents can work on one repository at once without stepping on each other.

Parallel tasks in worktrees

One worktree and branch per task. Give a task several directories and save the set as a workspace.

Review in the app

See the diff against the base commit, comment on lines and send the review back to the agent. Then commit, push and open a PR.

Ask from a note

Hover a heading and choose Ask. The session links to the heading and the result lands as a card under the section.

Crews and boards

Several sessions work as a team by role with a shared task list. Kanban boards are Markdown too.

Checks, phases and specs

Run a command after each turn, verify hidden acceptance criteria, or go research → plan → implement with a fresh context per phase.

Compare models

Run one task on 2 to 4 models, each in its own worktree, look at the diffs side by side and keep your favorite.

Inbox and queues

One inbox for what needs you and what waits to run: schedules and the requests and board cards you queue start from it one after the other, or as many at once as you set.

Follow-ups

An agent can set a follow-up for itself, such as checking a CI run later, and is resumed with its own note.

Notifications

A system notification and a Dock badge when a session finishes, fails or needs approval, with bursts combined into one.

Approvals and resume

Approval cards for tool calls, resume for interrupted sessions, and follow-ups while an agent is working.

Terminals built in

Terminal tabs next to your sessions, split into panes, for dev servers and builds.

Knowledge base

Markdown in, Markdown out

A request is a note. Its body is the prompt, and context: attaches pieces of other notes. When the session finishes, Marq writes the result back under ## Result and the full transcript to sessions/, also Markdown.

  • Plain files. Notes, requests, sessions, crews and boards are all .md files in a folder you own.
  • Any editor. Marq only rewrites the parts between its own markers.
  • Feeds back. Summaries and learnings go into the session note, and agents can search your vault.
notes/show-types-on-hover.md
---
type: request
status: todo
project: ~/dev/git/mq
context:
  - query: 'import "section" | nodes
      | section::find("Design") | section::body()'
    from: notes/design.md
---
# Show types on hover

Implement what the design note says.
terminal
# Learnings from every session
mq -A 'import "section"
  | section::find("Learnings")
  | section::body()' sessions/*.md

# Every command the agent ran
mq 'select(.code.lang == "tool:Bash")
  | .code.value' sessions/*.md
Query with mq

Hand the agent exactly what you pick

mq is a jq-like query language for Markdown, embedded in Marq. mq code blocks run in the preview and show their output right below.

  • Extract a section with mq, select text in a note or session, or attach context: queries to a request.
  • Reuse the same queries for the inbox, learnings across sessions and the Query tab.
  • Search past sessions by what was said or done in them.
